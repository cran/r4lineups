Introduction

r4lineups provides deep learning methods for measuring facial similarity in eyewitness lineups. These tools complement mock-witness studies by giving analysts reproducible, continuous similarity summaries that can help screen candidate foils and document how a lineup was assembled. They should be treated as exploratory aids, not as a replacement for mock-witness or outcome-based evidence.

Why measure face similarity?

Traditional lineup fairness assessment relies on mock witnesses viewing the lineup and choosing from it on the basis of a description. That dependence is the method’s foundation, and it is also where its difficulties lie.

Whose description? The mock-witness procedure asks people to pick the member who best matches a description, so the result is a property of the description-lineup pair, not of the lineup alone. Change the description and the measured fairness changes. In real cases the description is the witness’s own, given under conditions that may have been poor, and it is often the only one available. In laboratory studies it is frequently fabricated by the experimenters, which raises a different problem: a description written with a great deal of detail makes a lineup very hard to construct, because few candidate foils will match on every feature. Detail also tends to narrow the field towards the suspect, so an over-specified description can make a perfectly reasonable lineup look unfair — and an under-specified one can make an unfair lineup look acceptable.

Beyond that, the procedure requires recruiting and testing participants, which is slow and costly, and returns categorical data — which member each mock witness chose — rather than a continuous measure of resemblance.

Deep learning face similarity measures something different: the resemblance between the images themselves, with no description and no participants. It is numeric, fast, scalable to hundreds of lineups, and exactly reproducible — the same images always give the same scores. It can also say which foils sit close to or far from the suspect, which a choice distribution can only do indirectly.

An important caution before going further

It is tempting to move from “we can measure similarity” to “here is the right amount of similarity”, and this vignette deliberately does not do that.

The literature is not settled on how similar lineup foils should be. The long-standing intuition that foils should closely resemble the suspect competes with evidence that very high similarity can impair discriminability by removing the diagnostic features a witness might use, and the balance appears to depend on the procedure, the encoding conditions and what is being optimised. There is no agreed optimum, and no threshold at which a lineup becomes “fair” on a similarity metric.

So the functions here report degree of similarity; they do not grade it. Where the sections below give numbers, read them as descriptions of the images, not as verdicts on the lineup. Similarity scores are most defensible used comparatively — this foil against that one, this lineup against another constructed the same way — and as a screening aid during construction, rather than as evidence of fairness after the fact. The choice-based measures in the main vignette, and the outcome-based measures elsewhere in the package, remain the evidence about how a lineup actually performed.

Setup

Face similarity analysis uses Python’s DeepFace library via R’s reticulate package. This requires a one-time setup.

Check Current Setup

library(r4lineups)

# Check if Python and dependencies are available
check_python_deps()

Install Python Dependencies

If you don’t have the required dependencies, install them:

The setup has one requirement that must be met first, so do it in the order below.

TensorFlow, which DeepFace depends on, does not publish wheels for every Python version. At the time of writing it supports Python 3.9 to 3.13. If your system Python is newer — 3.14 or later, which is increasingly common — the install will proceed a long way and then fail with No matching distribution found for tensorflow. install_r4lineups_python() checks the interpreter first and stops before downloading anything, rather than letting that happen.

So pin the version, and obtain a suitable interpreter before asking for an environment built from one:

# Step 1: get a Python that TensorFlow supports. Skip if you already have one.
reticulate::install_python(version = "3.11")

# Step 2: build the environment from it and install DeepFace
install_r4lineups_python(envname = "r4lineups-face-env",
                         python_version = "3.11")

Requesting python_version = "3.11" without step 1 fails, because there is no 3.11 interpreter to build from. install_r4lineups_python() checks for this first and reports which versions it did find, along with the reticulate::install_python() call needed.

The first run takes several minutes, as it downloads the deep learning models (ArcFace, FaceNet and others). They are cached afterwards.

If the Python setup defeats you

It is a genuine possibility — the dependency chain is long and platform dependent. Two fallbacks:

  • The bundled Shiny application, run_r4lineups_app(), covers the lineup fairness measures that need no Python at all.
  • Everything in the rest of this package — effective size, functional size, ROC, CAC, the SDT and MPT models — is pure R. Two optional components use Python: face similarity, and the pyWitness bridge behind fit_lineup_models() (vignette("lineup_memory_models")). Neither is a prerequisite for anything else.

Basic Face Comparison

The simplest use case is comparing two face images.

Compare Two Faces

# Compare target to a foil
# (Use your own image paths)
result <- face_similarity(
  img1_path = "path/to/target.jpg",
  img2_path = "path/to/foil1.jpg",
  model = "ArcFace",     # Face recognition model (the package default)
  metric = "cosine"      # Similarity metric
)

print(result)

Understanding the Output

# Similarity score (for cosine, 1 - distance: -1 to 1, higher = more similar)
result$similarity  # e.g., 0.85

# Distance (lower = more similar)
result$distance    # e.g., 0.15

# Would the model judge these to be the same person?
result$verified    # see the note below on what this does and does not mean

# Model's threshold for verification
result$threshold   # e.g., 0.68 for ArcFace + cosine

Reading the output. similarity is a continuous score on the model’s own scale; higher means the two images are closer in the model’s embedding space. There is no table of bands here, because the literature does not establish what level of similarity a lineup foil ought to have. Compare scores against each other, not against a standard.

verified is a different kind of output. It is not a judgement about fairness; it is the model’s identity decision, whether the distance falls inside its threshold for “same person”. A TRUE is a reason to look at the two photographs, nothing more. Face recognition systems make false matches, especially between people of similar appearance, and a match does not establish that the photographs show the same person, that the foil fails as an alternative for witnesses, or that the lineup contains the suspect twice.

threshold is the model’s own cut-off for that identity decision. It is a distance, so on the similarity scale the corresponding value for cosine is 1 - threshold. It varies by model and metric, and it is not a fairness criterion.

Lineup Similarity Analysis

Analyze all lineup members against the target in one call.

Analyze Complete Lineup

# Paths to your own images; later chunks reuse these two objects
target_path <- "path/to/target.jpg"
foil_paths <- c(
  "path/to/foil1.jpg",
  "path/to/foil2.jpg",
  "path/to/foil3.jpg",
  "path/to/foil4.jpg",
  "path/to/foil5.jpg"
)

# Analyze all foils in a lineup. Rows come back ordered by rank, most similar
# first; foil_name and foil_path identify each foil.
lineup_result <- lineup_similarity(
  target_path = target_path,
  foil_paths = foil_paths,
  model = "ArcFace",
  metric = "cosine"
)

print(lineup_result)

Examining Results

# View as dataframe
lineup_result

# Summary statistics
summary(lineup_result)

# Foils the model judges to be the same identity as the suspect. Inspect
# them by eye; the model can be wrong.
same_identity <- lineup_result[which(lineup_result$verified), ]
if (nrow(same_identity) > 0) {
  cat("Model judges these foils to be the same person as the target:\n")
  # as.data.frame() first: a column subset keeps the lineup_similarity class,
  # whose print method needs the distance and verified columns
  print(as.data.frame(same_identity)[, c("foil_path", "similarity")])
}

# Check similarity distribution
cat("Mean similarity:", round(mean(lineup_result$similarity), 3), "\n")
cat("SD similarity:", round(sd(lineup_result$similarity), 3), "\n")
cat("Range:", range(lineup_result$similarity), "\n")

Describing the similarity profile

These numbers describe the similarity profile of the lineup — where the foils sit relative to the suspect and to each other. Turning that into a verdict would require knowing what profile is desirable, which is exactly what is unsettled.

Report three quantities:

  • Mean similarity — how close the foils are to the suspect on average.
  • Spread of similarity — whether the foils are homogeneous, or whether one or two sit much closer to the suspect than the rest. This is often the more informative of the two, since a lineup where one foil resembles the suspect far more than the others is unbalanced whatever the mean.
  • Identity matches — foils the model cannot distinguish from the suspect, as discussed above.
# Describe the similarity profile
mean_sim <- mean(lineup_result$similarity)
sd_sim <- sd(lineup_result$similarity)
n_verified <- sum(lineup_result$verified)

cat("Similarity profile:\n")
cat("  Mean similarity:", round(mean_sim, 3), "\n")
cat("  SD of similarity:", round(sd_sim, 3), "\n")
cat("  Range:", round(range(lineup_result$similarity), 3), "\n")
cat("  Foils judged same identity:", n_verified, "\n\n")

# The one flag raised automatically, because it is an identity decision
# rather than a fairness judgement
if (n_verified > 0) {
  cat("Note:", n_verified, "foil(s) judged the same person as the target.\n")
  cat("Inspect these photographs by eye; the model's match may be false.\n")
}

Models and Metrics

Different models and metrics serve different purposes.

Available Models

# List all models
available_models()

# The models differ in architecture, embedding size and speed. Published
# benchmarks measure accuracy at telling people apart, not agreement with human
# similarity judgements or with mock-witness choices, and the ranking depends
# on the benchmark and the installed version, so the package does not rank them.
# ArcFace is the default.

Distance Metrics

# Three metrics available:

# 1. Cosine (the default, and the only metric with a similarity score)
#    - Distance ranges from 0 to 2; similarity = 1 - distance, from -1 to 1
#    - Depends only on the angle between embeddings

# 2. Euclidean L2 (Euclidean distance between normalised embeddings)
#    - Still specific to the model: not comparable across models

# 3. Euclidean
#    - Raw vector distance, on each model's own scale

Comparing Models

# Compare different models on same lineup
models_to_test <- c("ArcFace", "Facenet512", "VGG-Face")

comparison_results <- list()

for (model in models_to_test) {
  result <- lineup_similarity(
    target_path = "path/to/target.jpg",
    foil_paths = foil_paths,
    model = model,
    metric = "cosine"
  )

  comparison_results[[model]] <- data.frame(
    model = model,
    mean_similarity = mean(result$similarity),
    sd_similarity = sd(result$similarity),
    n_verified = sum(result$verified)
  )
}

comparison_df <- do.call(rbind, comparison_results)
print(comparison_df)

Interpretation:

  • Models give different absolute scores, which are not comparable across models
  • Check whether the ordering of foils agrees across models; do not assume it
  • Use the same model consistently within a study

Batch Processing Multiple Lineups

# Process multiple lineups efficiently
lineup_list <- list(
  lineup1 = list(target = "target1.jpg", foils = c("1a.jpg", "1b.jpg", "1c.jpg")),
  lineup2 = list(target = "target2.jpg", foils = c("2a.jpg", "2b.jpg", "2c.jpg")),
  lineup3 = list(target = "target3.jpg", foils = c("3a.jpg", "3b.jpg", "3c.jpg"))
)

# Analyze all lineups
results_list <- lapply(names(lineup_list), function(lineup_name) {
  lineup <- lineup_list[[lineup_name]]

  result <- lineup_similarity(
    target_path = lineup$target,
    foil_paths = lineup$foils,
    model = "ArcFace"
  )

  # Add lineup identifier
  result$lineup_id <- lineup_name

  result
})

# Combine results
all_results <- do.call(rbind, results_list)

# Summary by lineup
library(dplyr)
lineup_summary <- all_results %>%
  group_by(lineup_id) %>%
  summarise(
    mean_similarity = mean(similarity),
    sd_similarity = sd(similarity),
    min_similarity = min(similarity),
    max_similarity = max(similarity),
    n_verified = sum(verified)
  )

print(lineup_summary)

Similarity and mock-witness choices: a hypothesis to test

The direction of the relationship is important here, and it is easy to state backwards. Mock witnesses choose the member who best matches the description. A foil that closely resembles the suspect also resembles the description, so it draws choices away from the suspect — which is precisely what makes a lineup fair. A foil that resembles the suspect very little matches the description poorly and tends to be chosen by nobody: it is a null foil, and it contributes nothing.

So the expectation runs: higher foil-suspect similarity should mean a higher share of mock-witness choices, and hence a larger effective size. That is a hypothesis, not an established result: embedding similarity is not human perceived similarity, and Lee, Mansour and Penrod (2024) report that different families of fairness measures can disagree. The sketch below shows the comparison to make; it is not a validated measure.

# Expected selection shares implied by similarity. Foils more similar to the
# suspect match the description better and should attract more choices.
similarities <- lineup_result$similarity
expected_prob <- similarities / sum(similarities)

# Compare to observed selections
# observed_prob <- table(mock_choices[-which(mock_choices == suspect_pos)]) /
#                  length(mock_choices[-which(mock_choices == suspect_pos)])

# A discrepancy between expected and observed shares is a question to
# investigate, not a validated measure of bias.

Practical Guidelines

Interpreting Similarity Scores

This vignette gives no similarity bands, for the reason set out at the start: no study has established what similarity a foil should have, and a band labelled “acceptable” would read as a finding when it is a guess. Two points in particular resist a simple rule. Low similarity between suspect and foils can make the suspect conspicuous, so it does not certify a fair lineup. And high similarity, or an identity match, is a reason to look at the photographs, not a verdict. Report the scores descriptively, compare them within a study, and use mock-witness and outcome data for claims about fairness.

Best Practices

  1. Consistency
    • Use same model throughout a study
    • Use same metric throughout a study
    • Use same verification thresholds
  2. Validation
    • Compare similarity scores to mock witness data when available
    • Treat any cut-off you adopt as a proposal to be tested, not a standard
  3. Complementarity
    • Use face similarity alongside traditional mock witness studies
    • Similarity describes the images; mock-witness and outcome data describe how the lineup performs
  4. Documentation
    • Report model and metric used
    • Report mean and SD of similarities
    • Report verification threshold and number verified
  5. Image Quality
    • Use high-quality, front-facing photos
    • Ensure good lighting and resolution
    • Consistent photo conditions across lineup members

Troubleshooting

“No face detected”

  • Image quality too poor
  • Face not front-facing enough
  • Try different detector: detector = "opencv" is more lenient

Embeddings fail

  • Check image file paths are correct
  • Ensure images are standard formats (jpg, png)
  • Verify Python environment is activated

Inconsistent results

  • Deep learning models are deterministic
  • If results change, check if images were modified
  • Verify same model/metric used

Very high/low similarities

  • Check image quality
  • Verify correct target-foil pairing
  • Look at the photographs before drawing any conclusion

Technical Details

What is computed

Each image is passed through a pretrained deep face-recognition network, which maps it to an embedding — a vector, typically 128 or 512 dimensional, positioned so that images of the same person land close together. Similarity between two faces is then a distance in that space, converted to a similarity score.

Component Meaning
model Which network produces the embedding (ArcFace, FaceNet, VGG-Face, …). Different networks give different embedding spaces, so scores are not comparable across models
metric How distance is measured in that space — cosine, Euclidean, or Euclidean on L2-normalised vectors
similarity For cosine, 1 − distance, from −1 to 1, higher meaning closer; NA for the Euclidean metrics
threshold The model’s own distance cut-off for judging two images the same identity (on the similarity scale, 1 - threshold for cosine). Model- and metric-specific
verified Whether the distance falls inside that threshold

Assumptions and limitations

  1. Scores are model-relative. ArcFace and FaceNet place faces in different spaces. Never compare a similarity score from one against another, and always report which model and metric produced a number.
  2. The networks were trained for recognition, not for lineup construction. They are optimised to tell identities apart, which is related to but not the same as capturing what makes two faces look alike to a witness. Whether the embedding distance corresponds to human perceived similarity is an empirical question, and the appropriate reference here is Tredoux (2002) on direct similarity measurement and its relation to human judgements.
  3. Image conditions are important. Pose, lighting, expression, resolution and background all affect embeddings. Lineup photographs taken under different conditions may differ in similarity for reasons that have nothing to do with facial resemblance. Standardised images are essential.
  4. Demographic differences in accuracy are well documented for face recognition systems, with error rates varying by ethnicity, sex and age. That is a serious caution in a forensic context, where the consequences of systematic error fall unevenly.
  5. No fairness threshold exists. The point of the caution at the top of this vignette, restated: these functions describe similarity, they do not adjudicate fairness.

Reproducibility

Given the same images, model and metric, scores are exactly reproducible — one of the method’s genuine advantages over mock-witness testing. Record the model, the metric and the package versions, since a different DeepFace release may ship different weights.
